# 시연 가이드 & AI 구성 설명

## 1. AI가 하는 일 / 하지 않는 일
| 단계 | 담당 | 내용 |
|---|---|---|
| 메뉴판 읽기 | **AI** (Groq Qwen 비전) | 사진 → 메뉴명·가격·원산지 추출 |
| 재료 조회 | 공공데이터 (메뉴젠 3,250종) | 재료·중량(g)·알레르기 정보 |
| 데이터에 없는 메뉴 | **AI** (Groq GPT-OSS) | 재료 추론 — 단, **태그만 부여하고 위험도는 판정하지 않음** |
| 재료 태그 보정 | 규칙 | 간장→밀, 김치→새우젓 등 누락 보완 |
| **위험도 판정** | **규칙 엔진 (AI 아님)** | 알레르기 22종·할랄·비건 규칙으로 계산 → 동일 입력에 동일 결과 |
| 직원 질문 문장 | 템플릿 (AI 아님) | "짬뽕에 새우가 들어가나요?" 자동 생성 |
| 직원 음성 답변 | **AI** (Groq Whisper) | 음성 → 텍스트 |
| 답변 반영 재판정 | 규칙 엔진 | 재료 확정/제외 후 재계산 |

> 한 줄 요약: **AI는 읽고 추론하고, 판정은 규칙이 한다.** LLM이 위험도를 직접 답하면 같은 질문에 다른 결과가 나올 수 있기 때문.

## 2. 시연 준비

**시연은 노트북의 로컬 서버로 한다.** 배포 서버(Render 무료)는 재시작하면 캐시 파일이 지워진다.

### 발표 전날
1. `.env` 확인 — `GROQ_VISION_MODEL`이 현재 제공 모델인지 (모델은 수시로 종료됨)
2. 시연할 메뉴판 사진을 `photos\demo` 폴더에 넣고, 서버를 켠 뒤:
   ```powershell
   python -m scripts.warm_cache --dir photos\demo
   ```
   `처음 N초 → 캐시 0.x초`가 나오면 준비 완료. 당일에는 성분 분석을 캐시에서 꺼낸다.
   (OCR이 당일 메뉴명을 다르게 읽은 메뉴만 AI를 부른다. 그때 Groq가 안 되면 요청 전체가 실패하지 않고
   해당 메뉴를 AI 없이 판정해 🟡 **직원 확인**으로 보여준다)
   (Groq 무료 등급은 **하루 토큰 한도**가 있어 당일 리허설로 한도를 다 쓰면 시연이 멈춘다)

### 프론트 화면 기준으로 확인한 조건 (2026-09-30, kfood-frontend main)
- **로그인한 상태로 시연해야 한다.** 프론트는 프로필을 로그인 토큰으로만 보낸다. 로그인하지 않으면 프로필이 없어서 전부 🟢로 나온다.
  시연 계정의 프로필에 `Shellfish`를 저장해둘 것.
- **결과 화면의 분석 제한시간이 30초다** (`ResultPage.jsx` `timeout: 30000`). 캐시를 채워두면 0.1초라 문제없지만,
  캐시가 빗나가 메뉴판 전체를 새로 분석하면 30초를 넘길 수 있다 → 프론트에 `120000`으로 늘려달라고 요청.
- **직원 답변 버튼(`/qna/confirm`)과 음성(TTS)은 아직 화면에 없다.** 결과 카드에 질문 문장만 보인다.
  "직원이 '안 들어가요' → 🟢로 바뀜" 장면은 프론트 작업 전까지 `http://localhost:8000/docs`에서 보여준다.

### 발표 당일
- **휴대폰 핫스팟 준비** — 메뉴판 사진 읽기(OCR)는 캐시되지 않아 인터넷이 필요하다
- 같은 노트북에서 서버 실행: `python -m uvicorn app.main:app`

### 시연 순서 (해물탕집 메뉴판, 알레르기 `shellfish`)
| 메뉴 | 판정 | 보여줄 점 |
|---|---|---|
| 해물조개전골 | 🔴 WARNING | 메뉴판 괄호에 적힌 `새우2`를 읽어서 판정 |
| 소갈비찜 | 🟢 SAFE | 해산물 없음 |
| 돼지국밥 | 🟡 CAUTION | 숨은 재료 → **"돼지국밥에 새우젓이 들어가나요?"** 직원 질문 |

돼지국밥 질문을 TTS로 읽어주고 → `/qna/confirm`에 "안 들어가요" → 🟢로 바뀌는 장면까지가 핵심.

## 3. 커버리지 개선 루프 (쓸수록 넓어지는 구조)
```
분석 중 미매칭 발생 → app/data/unmatched_menus.json 에 빈도 누적
   → GET /menus/unmatched 로 자주 나오는 메뉴 확인
   → 팀이 재료 검수 → python -m scripts.add_menu 로 메뉴 DB 추가
   → 다음부터 공공데이터처럼 즉시 판정
```
- **AI 추론 결과는 메뉴 DB에 자동으로 넣지 않는다.** 사람이 검수한 것만 DB에 들어간다(오류 데이터 축적 방지).
  - 속도를 위한 분석 캐시(`app/data/analysis_cache.json`)는 따로 있다. 같은 메뉴를 다시 볼 때 AI 호출을 생략할 뿐이고,
    화면에는 여전히 `AI 추정`으로 표시된다. 분석 로직이 바뀌면 `analysis_cache.VERSION`을 올려 옛 캐시를 버린다.
- 운영 API: `GET /menus/unmatched?limit=50`, `GET /menus/lookup?name=돈까스`
- 메뉴 추가: `python -m scripts.add_menu --list` 로 대기 목록 확인 후
  `python -m scripts.add_menu "돈까스" --required "돼지고기:pork" "빵가루:wheat" --hidden "돈까스소스:wheat,soy" --alias "돈가스"`
- 배포 환경에서 여러 사용자 수집을 모으려면 `supabase/migrations/09_unmatched_menus.sql` 적용
